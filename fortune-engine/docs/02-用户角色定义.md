# Fortune Engine - 用户角色与职责定义

## 02 | 用户角色分类

---

## 角色1：开发者 (Developer)

### 子类型

#### 1.1 前端开发者
**使用场景**：在微信小程序、App、网页中集成命理功能

**核心需求**：
- 简单易用的API
- 完整的TypeScript类型提示
- 详细的错误信息

**典型用例**：
```typescript
import { calculate } from 'fortune-engine';

const result = calculate({
  birthDate: '1990-01-01',
  birthTime: '12:30',
  gender: 'male'
});

console.log(result.pillars); // 四柱信息
```

**关注点**：
- API稳定性
- 文档完整性
- 示例代码丰富度

---

#### 1.2 后端开发者
**使用场景**：构建命理服务、批量计算、数据分析

**核心需求**：
- 高性能批量计算
- 数据持久化方案
- 可扩展的模块系统

**典型用例**：
```typescript
// 批量计算100个八字
const users = loadUsersFromDB();
const results = users.map(user =>
  calculate({
    birthDate: user.birthDate,
    birthTime: user.birthTime,
    gender: user.gender
  })
);
```

**关注点**：
- 性能优化
- 内存占用
- 并发处理能力

---

## 角色2：命理师 (Fortune Teller)

### 子类型

#### 2.1 专业命理师
**使用场景**：为客户提供命理咨询服务

**核心需求**：
- 排盘结果的**100%准确性**
- 详细的五行、十神、纳音分析
- 支持真太阳时等专业选项

**典型工作流**：
1. 客户提供出生信息
2. 使用Fortune Engine排盘
3. 根据结果进行解读
4. 提供咨询意见

**关注点**：
- 算法权威性（与古籍一致）
- 特殊情况处理（如子时、闰月）
- 结果可导出、打印

---

#### 2.2 命理学习者
**使用场景**：学习八字、梅花易数等传统知识

**核心需求**：
- 详细的计算过程说明
- 完整的理论文档
- 实际案例分析

**典型学习路径**：
1. 了解基础概念（天干、地支、五行）
2. 使用引擎验证手工计算结果
3. 通过示例学习断卦技巧
4. 掌握交互式占卜流程

**关注点**：
- 教育性文档
- 计算步骤透明化
- 经典案例库

---

## 角色3：研究者 (Researcher)

### 子类型

#### 3.1 算法研究者
**使用场景**：研究传统算法的现代实现

**核心需求**：
- 开源代码可审查
- 算法实现细节文档
- 可自定义和扩展

**研究方向**：
- 农历算法优化
- 节气计算精度提升
- 新的命理模块开发

**关注点**：
- 代码质量
- 算法复杂度
- 扩展性设计

---

#### 3.2 文化研究者
**使用场景**：研究传统文化的数字化保护

**核心需求**：
- 完整的古籍引用
- 算法的历史依据
- 文化传承记录

**研究价值**：
- 保护非物质文化遗产
- 推动传统知识现代化
- 学术论文数据支持

---

## 角色4：产品经理 (Product Manager)

**使用场景**：设计包含命理功能的产品

**核心需求**：
- 了解技术可行性边界
- API成本评估
- 用户体验优化

**典型决策**：
- 选择哪些功能集成
- 如何展示复杂结果
- 付费功能设计

**关注点**：
- 功能完整度
- 接口灵活性
- 商业化可能性

---

## 角色5：贡献者 (Contributor)

### 子类型

#### 5.1 代码贡献者
**职责**：
- 修复Bug
- 添加新功能
- 优化性能
- 完善测试

**贡献路径**：
1. Fork项目
2. 创建功能分支
3. 提交Pull Request
4. Code Review
5. 合并到主分支

---

#### 5.2 文档贡献者
**职责**：
- 完善API文档
- 翻译多语言文档
- 补充使用示例
- 整理常见问题

---

#### 5.3 数据贡献者
**职责**：
- 补充缺失的农历数据
- 提供更精确的节气计算
- 收集经典案例
- 验证算法准确性

---
