## 📖 文档详细说明

### 01 | 项目世界观与统一背景说明

**核心内容**：
- 项目定义（英文名、中文名、定位）
- 核心痛点分析
- SEO与技术关键词策略
- 成功标准（技术指标、业务指标）
- 项目愿景和非商业化声明

**关键信息**：
- 定位：专业级、开源的中国传统命理算法引擎
- 不是：娱乐性质的星座运势、塔罗牌应用
- 愿景：成为中国传统命理数字化的基础设施

**适合人群**：所有人（了解项目的第一步）

---

### 02 | 用户角色与职责定义

**核心内容**：
- 四大核心用户角色
  - 软件开发者
  - 命理研究者
  - 命理从业者
  - 开源贡献者
- 每个角色的典型场景
- 每个角色的核心需求

**关键信息**：
- 开发者：集成到App、网站、小程序
- 命理师：提高工作效率，专注解读
- 研究者：学习算法、验证理论
- 贡献者：完善功能、修复bug

**适合人群**：想了解如何使用本项目的人

---

### 03 | 业务现状与建设目标（As-Is / To-Be）

**核心内容**：
- 市场现状分析
  - 准确性问题
  - 碎片化严重
  - 缺乏开源方案
- 项目目标（To-Be）
- 衡量指标

**关键信息**：
- 市面工具问题：算法不准、工具分散、不透明
- 项目目标：准确、完整、开放、可扩展
- 成功指标：技术准确率99%+、性能<100ms、社区活跃

**适合人群**：PM、架构师、投资人

  - 体用确定规则
  - 五行生克规则
  - 互卦计算规则
  - 八卦类象规则
  - 交互式断卦规则
- 系统技术约束
- 输入校验规则
- 测试规则

**关键信息**：
- 所有算法的详细规则
- 边界条件处理
- 特殊情况说明
- 代码实现示例

**适合人群**：

### 08 | 非目标清单（Non-Goals）

**核心内容**：
- 八字模块不做什么
  - 不做商业化解读服务
  - 不做娱乐化运势内容
  - 不保证准确预测未来
  - 不做超出范围的命理系统
  - 不做移动端原生应用
  - 不做用户数据存储
- 梅花易数模块不做什么
  - 不做医疗健康占卜
  - 不做法律诉讼占卜
  - 不做AI/机器学习增强
  - 不做高频交易/博彩
  - 不做自动化批量占卜
- 系统架构不做什么
- 社区运营不做什么
- 决策流程指南

**关键信息**：
- 明确项目边界
- 避免误解和不当使用
- 保护项目定位
- 拒绝不合理需求的依据

**适合人群**：
- 所有人（避免误解）
- 贡献者（了解哪些PR会被拒绝）
- 用户（了解项目局限性）
