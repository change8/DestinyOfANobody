# 开发规范文档

## 1. 代码规范

### 1.1 TypeScript/JavaScript 规范

本项目遵循 **Airbnb JavaScript Style Guide** 和 **TypeScript 官方推荐规范**。

#### 1.1.1 命名规范

**变量和函数命名：**
```typescript
// ✅ 好的命名
const userName = 'John';
const calculateBaziPillars = (birthDate: Date) => { ... };
const isVipMember = true;

// ❌ 不好的命名
const un = 'John';
const calc = (d: Date) => { ... };
const flag = true;
```

**类命名（PascalCase）：**
```typescript
// ✅ 好的命名
class BaziCalculator { }
class UserService { }

// ❌ 不好的命名
class bazi_calculator { }
class user_service { }
```

**接口和类型命名：**
```typescript
// ✅ 接口使用 I 前缀（可选）或不用前缀
interface User { }
interface IBaziPillars { }

// ✅ 类型使用 Type 后缀（可选）
type UserInfoType = { };
type BaziResult = { };

// ❌ 不要使用 T 前缀
interface TUser { }  // 不推荐
```

**常量命名（UPPER_SNAKE_CASE）：**
```typescript
const TIANGAN_LIST = ['甲', '乙', '丙', '丁', '戊', '己', '庚', '辛', '壬', '癸'];
const MAX_RETRY_COUNT = 3;
const API_BASE_URL = 'https://api.destiny.com';
```

**枚举命名：**
```typescript
enum UserStatus {
  Active = 1,
  Inactive = 0,
  Banned = -1
}

enum Gender {
  Male = 'male',
  Female = 'female'
}
```

#### 1.1.2 代码格式

**缩进：** 使用 2 个空格

**引号：** 使用单引号

**分号：** 必须使用分号

**示例：**
```typescript
// ✅ 好的格式
const greeting = 'Hello';
const user = {
  name: 'John',
  age: 30
};

function sayHello(name: string): string {
  return `Hello, ${name}`;
}

// ❌ 不好的格式
const greeting = "Hello"  // 没有分号，使用双引号
const user={name:"John",age:30}  // 缺少空格
function sayHello(name:string):string{return `Hello, ${name}`}  // 单行函数体
```

#### 1.1.3 类型注解

**必须添加类型注解的地方：**
```typescript
// ✅ 函数参数和返回值
function calculateAge(birthDate: Date): number {
  const now = new Date();
  return now.getFullYear() - birthDate.getFullYear();
}

// ✅ 类的属性和方法
class User {
  private id: number;
  public name: string;

  constructor(id: number, name: string) {
    this.id = id;
    this.name = name;
  }

  public getId(): number {
    return this.id;
  }
}

// ✅ 接口定义
interface BaziPillars {
  year: Pillar;
  month: Pillar;
  day: Pillar;
  hour: Pillar;
}
```

**可以省略类型注解的地方：**
```typescript
// ✅ 明显可以推断的类型
const count = 0;  // number
const name = 'John';  // string
const users = [{ id: 1, name: 'John' }];  // Array<{ id: number, name: string }>
```

### 1.3 Git 提交规范

**Commit Message 格式（Conventional Commits）：**

```
<type>(<scope>): <subject>

<body>

<footer>
```

**类型（type）：**
- `feat`: 新功能
- `fix`: 修复bug
- `docs`: 文档更新
- `style`: 代码格式调整（不影响功能）
- `refactor`: 重构（不是新功能也不是修复bug）
- `perf`: 性能优化
- `test`: 测试相关
- `chore`: 构建工具、依赖更新等

**作用域（scope）：**
- `bazi`: 八字模块
- `yijing`: 易经模块
- `user`: 用户模块
- `server`: 后端
- `miniprogram`: 小程序
- `engine`: 算命引擎

**示例：**
```bash
# ✅ 好的提交
git commit -m "feat(bazi): 添加大运流年计算功能"
git commit -m "fix(yijing): 修复六爻起卦动爻判断错误"
git commit -m "docs: 更新API文档"
git commit -m "refactor(engine): 重构天干地支计算逻辑"

# ❌ 不好的提交
git commit -m "修改了一些东西"
git commit -m "fix bug"
git commit -m "update"
```

**详细示例：**
```
feat(bazi): 添加人生K线图可视化功能

- 实现基于大运流年的K线数据计算
- 集成 echarts 绘制K线图
- 添加年份点击事件查看详情

Closes #123
```

## 3. Git 工作流

### 3.1 分支策略

采用 **Git Flow** 工作流：

```
main (生产分支，受保护)
  ↑
  └─ release/* (预发布分支)
       ↑
       └─ develop (开发分支)
            ↑
            ├─ feature/* (功能分支)
            ├─ bugfix/* (bug修复分支)
            └─ hotfix/* (紧急修复分支，从main拉取)
```

**分支命名规范：**
```
feature/bazi-calculator      # 功能分支
feature/user-profile         # 功能分支
bugfix/fix-pillar-error      # bug修复分支
hotfix/fix-login-crash       # 紧急修复分支
release/v1.0.0               # 发布分支
```

### 3.2 开发流程

**1. 创建功能分支：**
```bash
# 从 develop 分支创建新功能分支
git checkout develop
git pull origin develop
git checkout -b feature/bazi-calculator
```

**2. 开发并提交：**
```bash
# 小步提交，每个提交只做一件事
git add .
git commit -m "feat(bazi): 添加年柱计算函数"

git add .
git commit -m "feat(bazi): 添加月柱计算函数"
```

**3. 推送到远程：**
```bash
git push -u origin feature/bazi-calculator
```

**4. 创建 Pull Request：**
- 在 GitHub/GitLab 上创建 PR
- 填写 PR 描述（功能说明、测试情况）
- 指定审查人
- 关联相关 Issue

**5. 代码审查：**
- 至少一人审查通过
- CI/CD 测试通过
- 解决所有审查意见

**6. 合并到 develop：**
```bash
# 使用 Squash and Merge（推荐）或 Merge
# 合并后删除功能分支
```

**7. 发布流程：**
```bash
# 创建发布分支
git checkout -b release/v1.0.0 develop

# 测试、修复bug

# 合并到 main 和 develop
git checkout main
git merge release/v1.0.0
git tag -a v1.0.0 -m "Release version 1.0.0"
git push origin main --tags

git checkout develop
git merge release/v1.0.0
git push origin develop
```

## 4. 测试规范

### 4.1 测试原则

**测试金字塔：**
```
       /\
      /  \  E2E测试（少量）
     /----\
    /      \  集成测试（适量）
   /--------\
  /          \  单元测试（大量）
 /------------\
```

**测试覆盖率要求：**
- 核心算法（fortune-engine）：**80%+**
- 业务逻辑（services）：**70%+**
- 控制器（controllers）：**60%+**
- 整体覆盖率：**70%+**

### 4.2 单元测试规范

**测试文件命名：**
```
bazi-calculator.ts       → bazi-calculator.spec.ts
user.service.ts          → user.service.spec.ts
```

**测试结构（AAA模式）：**
```typescript
describe('BaziCalculator', () => {
  describe('calculateYearPillar', () => {
    it('should calculate correct year pillar for 1990-01-01', () => {
      // Arrange（准备）
      const calculator = new BaziCalculator();
      const birthDate = new Date('1990-01-01');

      // Act（执行）
      const result = calculator.calculateYearPillar(birthDate);

      // Assert（断言）
      expect(result.gan).toBe('己');
      expect(result.zhi).toBe('巳');
    });

    it('should throw error for invalid date', () => {
      const calculator = new BaziCalculator();
      const invalidDate = new Date('invalid');

      expect(() => {
        calculator.calculateYearPillar(invalidDate);
      }).toThrow(InvalidDateError);
    });
  });
});
```

**测试用例覆盖：**
- 正常情况
- 边界情况
- 异常情况

**运行测试：**
```bash
# 运行所有测试
npm test

# 运行特定文件测试
npm test bazi-calculator.spec.ts

# 生成覆盖率报告
npm run test:cov

# 监听模式
npm run test:watch
```

## 9. 性能规范

### 9.1 前端性能

**小程序性能要求：**
- 首屏加载时间 < 3秒
- setData 调用频率 < 60次/秒
- 单次 setData 数据 < 256KB
- 使用分包加载

**优化技巧：**
```javascript
// ✅ 好的做法
this.setData({
  'list[0].name': 'new name'  // 局部更新
});

// ❌ 不好的做法
const list = this.data.list;
list[0].name = 'new name';
this.setData({ list });  // 全量更新
```

### 9.2 后端性能

**响应时间要求：**
- 接口响应时间 P95 < 200ms
- 数据库查询 < 100ms
- 缓存命中率 > 80%

**优化建议：**
- 使用索引
- 分页查询
- 使用缓存
- 避免N+1查询
