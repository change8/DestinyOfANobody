# 数据库设计文档

## 1. 数据库概述

### 1.1 数据库选型

本项目采用**多数据库架构**：

- **MySQL 8.0+**：存储结构化数据（用户、订单、会员等）
- **MongoDB 5.0+**：存储半结构化数据（排盘记录、卦象详情等）
- **Redis 6.0+**：缓存层（排盘结果、会话、热点数据等）

### 1.2 命名规范

**表名规范：**
- 使用小写字母和下划线
- 使用复数形式（如 users, orders）
- 关联表使用下划线连接（如 user_vip）

**字段名规范：**
- 使用小写字母和下划线
- 主键统一使用 `id`
- 外键使用 `{表名}_id`
- 布尔类型使用 `is_` 前缀
- 时间字段使用 `_at` 后缀

### 2.2 核心表设计

#### 2.2.1 用户表 (users)

**表说明：** 存储用户基本信息

```sql
CREATE TABLE `users` (
  `id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `openid` VARCHAR(64) NOT NULL COMMENT '微信openid',
  `unionid` VARCHAR(64) DEFAULT NULL COMMENT '微信unionid',
  `nickname` VARCHAR(50) DEFAULT NULL COMMENT '昵称',
  `avatar_url` VARCHAR(255) DEFAULT NULL COMMENT '头像URL',
  `gender` TINYINT DEFAULT 0 COMMENT '性别：0未知 1男 2女',
  `phone` VARCHAR(20) DEFAULT NULL COMMENT '手机号',
  `status` TINYINT DEFAULT 1 COMMENT '状态：0禁用 1正常',
  `is_vip` TINYINT DEFAULT 0 COMMENT '是否会员：0否 1是',
  `vip_expire_at` DATETIME DEFAULT NULL COMMENT '会员过期时间',
  `last_login_at` DATETIME DEFAULT NULL COMMENT '最后登录时间',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`),
  KEY `idx_unionid` (`unionid`),
  KEY `idx_phone` (`phone`),
  KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | 是 | 主键，自增 |
| openid | VARCHAR(64) | 是 | 微信openid，唯一 |
| unionid | VARCHAR(64) | 否 | 微信unionid（开放平台） |
| nickname | VARCHAR(50) | 否 | 用户昵称 |
| avatar_url | VARCHAR(255) | 否 | 头像URL |
| gender | TINYINT | 否 | 性别 |
| phone | VARCHAR(20) | 否 | 手机号（绑定后） |
| status | TINYINT | 否 | 账号状态 |
| is_vip | TINYINT | 否 | 是否会员 |
| vip_expire_at | DATETIME | 否 | 会员过期时间 |

### 2.3 索引设计说明

**索引原则：**
1. 主键自动创建唯一索引
2. 外键字段创建普通索引
3. 经常查询的字段创建索引
4. 组合查询使用联合索引

**重要索引：**
- `users.openid`：唯一索引，登录认证
- `bazi_records.user_id`：普通索引，查询用户记录
- `bazi_records.birth_timestamp`：普通索引，按生辰查询
- `orders.order_no`：唯一索引，订单查询

## 4. Redis缓存设计

### 4.1 缓存Key设计规范

**命名格式：** `{项目前缀}:{模块}:{业务}:{标识}`

**示例：**
```
destiny:bazi:result:1990-01-01-12:30:male     # 八字排盘结果
destiny:user:info:123456                      # 用户信息
destiny:token:abc123def456                    # JWT Token
destiny:kline:1990-01-01-12:30:male           # K线数据
```

### 4.2 缓存策略

#### 4.2.1 八字排盘结果缓存

```
Key: destiny:bazi:result:{birth_timestamp}:{gender}
Value: JSON字符串（完整排盘结果）
TTL: 7天（604800秒）

示例：
destiny:bazi:result:631152600:male
```

#### 4.2.2 用户信息缓存

```
Key: destiny:user:info:{user_id}
Value: Hash类型
TTL: 1天（86400秒）

字段：
- id
- openid
- nickname
- avatar_url
- is_vip
- vip_expire_at
```

#### 4.2.3 JWT Token缓存

```
Key: destiny:token:{token}
Value: user_id
TTL: 7天（604800秒）
```

#### 4.2.4 热门知识库缓存

```
Key: destiny:knowledge:hot
Value: List类型（文章ID列表）
TTL: 1小时（3600秒）
```

#### 4.2.5 API限流缓存

```
Key: destiny:ratelimit:ip:{ip}
Value: 请求次数
TTL: 1分钟（60秒）

Key: destiny:ratelimit:user:{user_id}
Value: 请求次数
TTL: 1分钟（60秒）
```

## 6. 数据迁移与备份

### 6.1 数据迁移

**MySQL迁移脚本位置：** `/server/database/migrations/`

**执行迁移：**
```bash
npm run migration:run
```

**回滚迁移：**
```bash
npm run migration:revert
```

### 6.2 数据备份策略

**MySQL备份：**
- 全量备份：每天凌晨2点
- 增量备份：每4小时
- 保留周期：30天

**MongoDB备份：**
- 全量备份：每天凌晨3点
- 保留周期：30天

**Redis备份：**
- RDB快照：每天凌晨4点
- AOF持久化：开启

## 7. 数据安全

### 7.1 敏感数据加密

**加密字段：**
- 用户手机号（使用AES-256加密）
- 生辰信息（可选加密）

### 7.2 数据访问控制

**权限控制：**
- 用户只能访问自己的排盘记录
- 公开记录可以通过分享码访问
- 管理员可访问所有数据（带审计日志）
